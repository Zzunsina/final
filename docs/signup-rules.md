# 회원가입·로그인 규칙 변경

## 최신 규칙

- 일반·관리자 로그인은 loginId로만 조회합니다. email 필드나 이메일 주소로는 로그인하지 않습니다.
- 일반 로그인에 개인·기업 선택을 추가했습니다. 선택 유형과 DB 역할이 일치해야 하며 ADMIN은 일반 로그인 API에서 쿠키를 발급받을 수 없습니다. ADMIN 값을 변조해 보내는 것도 거절합니다.
- 일반 로그인 제목은 '새로운 기회를 연결하세요.', 영문 안내는 'JOBBRIDGE LOGIN'입니다.
- 회원가입 아이디 라벨은 '아이디 (영문·숫자, 4~30자)'이며 입력 검증은 그대로 유지합니다.
- 일반 로그인 폼 바로 아래 관리자 로그인 링크를 제거했습니다. 관리자 화면 /admin/login과 푸터 진입 링크는 유지합니다.
- 상단 회원가입은 로그인과 같은 배경 없는 텍스트 링크입니다.
- 신규 아이디는 영문·숫자만 4~30자입니다. 화면에서 다른 문자를 제거하고 서버에서도 검사합니다. 저장은 소문자로 정규화합니다.
- 신규 비밀번호와 비밀번호 변경은 공백 없이 8~20자입니다. 기존 비밀번호가 긴 계정은 기존 비밀번호로 로그인한 후 새 규칙에 맞춰 변경할 수 있습니다.
- 구직자·기업 가입에 생년월일 8자리(예: 20000123), 성별 남자/여자를 필수 추가했습니다.
- 생년월일의 실제 날짜·윤년·미래 날짜를 서버에서 검증합니다. gender는 MALE/FEMALE만 허용합니다.
- 생년월일과 성별은 users에 저장합니다. 구직자는 job_seekers.birth_date도 함께 저장·수정합니다.
- 생년월일·성별은 공개 기업·공고 응답이나 기업에 전달하는 지원 연락처 스냅샷에 추가하지 않았습니다.

## 기존 회원

Flyway V6는 기존 아이디를 유지합니다. 아이디가 NULL/빈 값인 기존 회원에게만 member<user_id>를 부여합니다.
이미 사용 중이면 x1, x2 등의 접미사를 붙여 중복을 피합니다. 예전 아이디의 밑줄·하이픈을 임의 변경하지 않습니다.
기존 생년월일은 복사하되 알 수 없는 성별을 임의로 추정하지 않습니다.

관리자가 HeidiSQL에서 기존 계정 아이디를 확인하려면 다음 읽기 전용 쿼리를 사용합니다.

```sql
SELECT user_id, login_id, email, role FROM users ORDER BY user_id;
```

## 적용

IntelliJ 서버를 중지 후 다시 실행하면 V6가 자동 적용됩니다.
VS Code의 npm run dev를 유지한 채 브라우저를 새로고침합니다.
기존 계정은 이메일 대신 기존 아이디 또는 위 쿼리로 확인한 자동 부여 아이디로 로그인합니다.

## 검증

- 백엔드 테스트 10개 통과(이메일 로그인 거절, 아이디 문자, 비밀번호 길이·공백, 생년월일·성별 저장, 윤년·미래 날짜, 기존 계정 migration 충돌 포함).
- 프런트 lint·build 통과.
- 브라우저에서 로그인 필드·링크 제거·상단 텍스트 링크, 가입 필드와 선택 항목을 확인했습니다.
