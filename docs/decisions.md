# 구현 결정과 제한

## 2026-10-20

1. 루트는 사용자가 연 작업 폴더 `C:\JobBridge`로 정했습니다. 원본 첨부는 수정하지 않고 사본을 보관했습니다.
2. 첨부 개요서의 예시 프롬프트는 별도 실행 권한으로 취급하지 않았습니다. 사용자 요청인 프로젝트 제작 범위 안에서 명세를 참고했습니다.
3. 원본 `DataBase.txt`, 구조도 두 파일, CSS 선택자 파일은 미제공입니다. 개요서의 12개 테이블·역할·상태를 재구성했습니다. SQL 원본과 완전히 일치한다고 보장하지 않습니다.
4. 외부 DB 설치 없이 실행할 수 있게 `dev` H2 파일 DB를 추가했습니다. 기본 프로필은 MySQL입니다. 스키마 변경은 Flyway V1~V3, 자동 데이터 삭제·재생성은 사용하지 않습니다.
5. 데이터 접근은 Spring JDBC `Database` Repository를 채택했습니다. 트랜잭션과 `FOR UPDATE` 잠금은 서비스에서 처리합니다. JPA 의존성·validate 설정은 남아 있지만 실제 JPA Entity/Repository는 없습니다. 따라서 JPA validate가 현재 SQL 스키마를 검증하는 것은 아닙니다. 도메인별 Entity·DTO·Repository로 세분화하는 제안은 미완료입니다.
6. API 응답은 명시적 SELECT 열과 스냅샷으로 제한합니다. 서버의 회원·소유권·기업 승인 검증을 각 API에서 수행합니다. 프런트 Guard만 신뢰하지 않습니다. 현재 전용 record DTO 대신 응답 Map을 사용합니다.
7. JWT는 HS256으로 서명하고 서버에 access/refresh SHA-256 해시를 보관합니다. 임의 클라이언트 role을 권한으로 사용하지 않습니다. 세션 취소·refresh 회전·최종 만료는 DB로 확인합니다.
8. 보안 필터는 CSRF·인증 복원을 담당하고 각 보호 Controller가 공통 AuthService로 역할을 검사합니다. `/api/**` 필터 permitAll은 각 Controller의 서버 검사와 함께 사용됩니다. 새로운 API를 추가할 때 동일 검사를 반드시 적용해야 합니다. 미정의 경로는 매핑되지 않습니다.
9. 재설정 토큰 테이블은 준비했지만 SMTP·일회용 재설정 처리 전체는 구현하지 않았습니다. 요청은 명시적 503이며 발송 완료로 표시하지 않습니다.
10. 기업 진위는 관리자 수동 승인으로 제한합니다. 사업자번호 형식·중복 검사와 실제 진위 확인은 다릅니다.
11. 면접의 내부 평가(result)와 메모(memo)는 구직자에게 반환하지 않습니다. 기업 화면에서는 면접 등록·조회, 수정·상태 처리 API는 서버에 제공합니다.
12. 기업과 관리자 목록은 MVP에서 최대 100건, 기업 공개 목록은 전체 조회입니다. 대량 운영 페이지·검색·선택 UI 개선은 후속 범위입니다.
13. 개요서의 프런트 개별 파일 구조는 역할별 페이지 모듈로 묶었습니다. 공통 폼·상태·카드를 재사용합니다. 지역·경력 선택, 제출 스냅샷과 서버 검증을 우선 연결했습니다.
14. 개발 패키지는 고정 버전과 npm lock을 제공합니다. 공급망 업데이트·운영 취약점 점검을 수행했다고 주장하지 않습니다.
15. 외부 SMTP·문자·사업자 조회·소셜 로그인·AI 매칭·배포·운영 개인정보 정책은 설정하거나 실행하지 않았습니다.

- SMTP 재설정 처리, 운영 관리자 생성, 공유 저장소 기반 요청 제한.
- 관리자·기업 목록 페이지와 필터, 기업 검색·기업별 공고 목록.
- 면접 수정·완료·취소 화면, 문의 단독 상세 라우트, 구직자 상세정보 입력 화면.
